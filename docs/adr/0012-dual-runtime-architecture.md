# 双运行时架构：Python 确定性内核 + Agent 仪式层，告警走邮件

仪式驱动（ADR-0010）要求快照按时发生、周报被生成、告警主动送达——与 Streamlit"打开才计算"模型根本冲突。裁决采用双运行时：

1. **Python 确定性内核**：账本计算、体制引擎、快照写入、信号评估，全部可 headless 运行（`uv run python -m jobs.<name>`），保持纯函数 + 文件持久化。所有数字唯一出自这里（仓位单一出处的技术保障）。
2. **Agent 仪式层**：周报/月审/年审由排程的 Agent 会话执行（Cursor Automation / Claude Code 定时任务）。Agent 负责：调天天基金 Skill 拉基金数据写入账本、运行确定性脚本取数、装配与叙事、把周报 markdown 落盘到 repo。Agent 不产生数字。
3. **Streamlit 降级为纯查阅层**：渲染账本、引擎状态、已生成的周报，不承担"打开时现算"。
4. **主动告警（哨兵触发、逻辑破坏）经邮件送达**：可靠、可归档、不依赖额外服务商。

关键依据：天天基金数据链路只存在于 Agent Skill 形态（`ttfund-*` skills），无公开 API；把它重实现为 Python 客户端是最脆弱且不值得维护的路径。

## Considered Options

- **单一 Python 运行时**（LLM 走 API、基金数据手工导出）：被否——天天基金链路重实现成本高且脆弱，手工导出违背半自动账本（ADR-0007）。
- **Streamlit 懒加载补算**：被否——快照日期由用户打开习惯决定，时间序列千疮百孔；"打开才知道哨兵触发"等于没有告警。
