# P1 约束层改造 + 去糟粕

## Problem Statement

P0 账本已经能回答"我的真实暴露是什么"，但工具里同时存在着两套互相打架的逻辑：

1. **被裁决废弃的东西仍在诱导操作**：交易策略页的金字塔仓位（40/30/20/10）、固定止损止盈（-6.5%/+25%/+45%/跟踪止损）、体制仓位乘数横幅（BULL→1.0）每天都在产出仓位数字，与"仓位单一出处"原则（ADR-0006）直接冲突——我一打开页面就看到不该看的建议。
2. **宏观引擎悬空**：美股/A 股的 Target Position Envelope 只停留在展示层和 CSV 历史，不约束任何东西；它没有接入账本，"偏离基准"的判定缺少"引擎许可什么"这半边。
3. **Position Advisor 还是上一个时代的产物**：靠手工上传 CSV 喂数据，内含与我实际操作无关的 options/beta_spx 逻辑，且它的 conviction×体制仓位上限矩阵自己也在产仓位数字。
4. **北向信号采信了已停披露的数据**：2024-08 之后的日度"净买入"是估算值，±5% Utilization 调整建立在被污染的数据上（ADR-0009）。
5. **港股是盲区**：直接持有的港股标的取价返回 None，也没有体制约束视图——而它在我账本里是独立市场类别。

## Solution

四个切片，按依赖顺序执行（1 先行，删掉的代码不用改）：

**切片 1 — 去糟粕（ADR-0006）**：从趋势模块与交易策略页拆除金字塔仓位、固定止损止盈、体制仓位乘数映射；交易计划文本重写为只含标的确认、入场时机、纪律红线三栏。保留趋势确认清单（6 项）、趋势阶段判断（5 阶段）、衰竭信号清单（9 项）——它们回答"现在是不是好的买卖时点"，不产仓位数字。

**切片 2 — Position Advisor 重构 + 北向信号替换（ADR-0009）**：Advisor 数据源从 CSV 手工上传改为总资产账本（只读门面）；砍掉 options/beta_spx 专属逻辑与 conviction×体制仓位上限矩阵（后者违反弹位单一出处）；保留并扩展 conviction 分级（S/A/B/C，扩展到 A 股/港股，基金 conviction 手工维护直到 P3 替代性审查上线）与减仓优先级排序（低信念先砍 → 高波动先砍 → 盈利仓先砍，全市场通用）。北向信号弃用日度净买入，改用「成交总额（活跃度）+ 季度持股变动（方向）」组合替换原 ±5% Utilization 调整项。

**切片 3 — 战略基准区间 + envelope 降级接入总资产层（ADR-0002/0003）**：envelope 引擎本体不动，新增战术偏移纯函数：把某市场 envelope（0–100% 市场内仓位）线性映射到该市场基准区间 [min, max]，得到该市场核心仓占总资产的**当期许可区间**——映射结果天然 clamp 在基准区间内，引擎从"该配几成仓"变为"熊市里许可减到多少"（ADR-0003 的下行许可定位）。账本门面新增只读聚合输出各市场许可区间，总资产页与市场约束页据此渲染。

**切片 4 — 港股合成视图（ADR-0008）**：不建第三套引擎。港股体制约束由 A 股引擎 × 美股 L1 合成（逐字段取更保守值）；废弃股票取数的"港股返回 None" placeholder，港股日线经 yfinance `.HK` 补齐；南向资金保留为港股专属展示指标。

全程遵守：仓位数字只出自总资产层（ADR-0006）；卫星仓上限 35%（ADR-0018）；新文案只注册中文 key（ADR-0016）；import 边界（ADR-0017）。

## User Stories

### 切片 1 — 去糟粕

1. 作为个人投资者，我想让交易策略页不再出现金字塔仓位建议（40/30/20/10），这样我不会被诱导按短线仓位系统操作
2. 作为个人投资者，我想让趋势分析输出不再包含固定止损止盈价格（-6.5%/+25%/+45%/跟踪止损），这样买卖纪律由我在总资产层决定，而非技术模块代劳
3. 作为个人投资者，我想让交易策略页不再出现体制仓位乘数横幅（BULL→1.0 等映射），这样体制信息不再以仓位数字的形式出现
4. 作为个人投资者，我想让"一键生成交易计划"文本只包含标的确认、入场时机、纪律红线三栏，这样它仍然是我交易前的检查清单，而不是仓位指令
5. 作为个人投资者，我想让趋势确认清单（6 项）、趋势阶段判断（5 阶段）、衰竭信号清单（9 项）完整保留且行为不变，这样"交易时参考"的能力不因拆除而受损
6. 作为代码维护者，我想让被删逻辑无残留（无注释僵尸、无死配置、无孤儿 i18n key），这样代码库不留双口径

### 切片 2 — Position Advisor 重构 + 北向

7. 作为个人投资者，我想让 Position Advisor 直接读总资产账本的持仓数据，这样我不再需要手工导出上传 CSV，且 Advisor 看到的永远是最新账本事实
8. 作为个人投资者，我想让 Advisor 的持仓视图覆盖 A 股/港股/美股/基金四类资产，这样减仓优先级排序是全市场通用的
9. 作为个人投资者，我想给任意市场的个股打 conviction 分级（S/A/B/C），这样信念分层不再只属于美股
10. 作为个人投资者，我想让 Advisor 不再出现 options 名义本金、beta_spx 相关栏目，这样界面只反映我真实的操作世界
11. 作为个人投资者，我想让减仓优先级排序按「低信念先砍 → 高波动先砍 → 盈利仓先砍」输出，且波动率改用标的历史波动率（52 周）而非 beta_spx，这样排序依据对全市场标的都成立
12. 作为个人投资者，我想让 Advisor 不再输出任何仓位上限/目标仓位数字（conviction×体制矩阵废弃），这样仓位数字的唯一出处是总资产层
13. 作为个人投资者，我想让 A 股流动性分析中的北向信号改用成交总额（活跃度）与季度持股变动（方向），这样它不再采信 2024-08 后已停披露的日度"净买入"估算值
14. 作为个人投资者，我想让原 ±5% Utilization 日度调整项被新组合信号替换，且新阈值的来源与方向性理由写入配置（ADR-0009 阈值治理），这样每个魔法数字都可问责
15. 作为个人投资者，我想在 UI 上看到北向数据口径变更的披露说明（日度净买入已停披露、现为估算值不采信），这样我知道信号的基础是什么
16. 作为代码维护者，我想让 `northbound_flow.csv` 中 2024-08 之后的"净买入"列不再被任何计算读取，这样污染数据被物理隔离

### 切片 3 — envelope 接入总资产层

17. 作为个人投资者，我想让每个市场（A 股/美股）的 envelope 被映射为「该市场核心仓占总资产的当期许可区间」，且该区间永不突破战略基准区间，这样宏观引擎的约束第一次落到我的总资产上
18. 作为个人投资者，我想在总资产页看到各市场「实际占比 vs 基准区间 vs 引擎许可区间」三层对照，这样我能一眼区分"偏离基准"和"超出引擎许可"
19. 作为个人投资者，我想让基准未设定时许可区间视图显示"先定基准"的引导而非报错，这样 P0 的渐进引导行为不被破坏
20. 作为个人投资者，我想让 envelope 引擎本身的计算逻辑与历史 CSV 格式保持不变，这样体制引擎的历史序列与既有测试不受 P1 影响
21. 作为个人投资者，我想让引擎许可区间只是约束视图，不构成自动交易指令，这样"下行许可"的定位（ADR-0003）不被误读为择时信号
22. 作为代码维护者，我想让战术偏移映射是纯函数（envelope + 基准区间 → 许可区间），这样它可以脱离 UI 与网络被完整测试

### 切片 4 — 港股合成视图

23. 作为个人投资者，我想让港股标的的日线数据经 yfinance `.HK` 正常取价，这样"港股返回 None"的盲区被消除，账本快照里港股估值不再降级
24. 作为个人投资者，我想看到港股的体制约束视图——由 A 股引擎 × 美股 L1 逐字段取更保守值合成，这样港股约束反映"中国基本面 × 美元流动性"的真实定价结构，且维护面不增加第三套引擎
25. 作为个人投资者，我想让港股许可区间同样以基准区间为笼（与切片 3 同一映射机制），这样三个市场的约束口径一致
26. 作为个人投资者，我想让南向资金指标保留为港股专属展示，这样港股页有它特有的资金面参考
27. 作为个人投资者，我想让港股合成逻辑是纯函数（A股 envelope + 美股 L1 → HK 约束），这样合成规则可测试、可问责

### 横切

28. 作为个人投资者，我想让 P1 全程不产出任何新的英文 i18n key（ADR-0016），这样语言策略不倒退
29. 作为代码维护者，我想让账本域与 jobs 不 import UI 层、UI 只读不写（ADR-0017），这样架构边界在改造中不被侵蚀
30. 作为个人投资者，我想让卫星仓 35% 上限（ADR-0018）在所有相关视图（含 Advisor、约束视图）中口径一致，这样不残留 25% 旧数字

## Implementation Decisions

- **切片边界 = 四个独立可交付单元**，建议执行顺序 1 → 2 → 3 → 4（先去糟粕缩小后续重构表面积；3 与 4 有轻度耦合——4 复用 3 的映射机制，故 4 排最后）。
- **去糟粕的删除清单**（以 ADR-0006 为准）：趋势模块中的金字塔计算与固定止损止盈常量/函数；交易策略 UI 中的金字塔计算器、体制乘数映射与横幅；交易计划文本生成器重写（保留入口，重写输出结构为标的确认/入场时机/纪律红线）；关联 i18n key 与 `regime_defaults.yaml` 中的死配置一并清理。保留的清单/阶段/衰竭逻辑代码不动。
- **Position Advisor 重构**：数据源改为账本门面只读接口（持仓 + 快照）；删除 Holding 模型的 options/beta_spx 字段及一切派生逻辑、conviction×体制仓位上限矩阵及其配置；波动率改由账本 QuoteProvider 的历史价格计算（52 周年化波动率）；新增 Ledger→Advisor 适配层（薄，只做数据形状转换，不含业务规则）；CSV 上传入口与解析器删除。conviction 存储进账本（主线映射表扩展或独立表，实施时裁定），基金 conviction 手工维护。
- **北向信号替换**：新信号函数（纯函数）输入为成交总额序列 + 季度持股变动，输出活跃度/方向调整；阈值写入配置并标注来源与方向性理由（ADR-0009）；取数层读取路径切断对 2024-08 后净买入列的依赖；UI 披露口径变更说明。季度持股数据源在实施时裁定（Tushare/AkShare 可用性验证），若季度数据不可得则降级为"仅活跃度"并显式标注。
- **战术偏移映射**（切片 3 核心规则）：`许可区间 = baseline_min + envelope × (baseline_max − baseline_min)` 的线性映射，对 envelope 的 min/max 分别映射——结果必落在基准区间内（ clamp 免费）。该函数为纯函数，挂在账本域；门面新增只读聚合（实际占比、基准区间、许可区间三元组按市场输出）。
- **港股合成**（切片 4 核心规则）：`HK 约束 = elementwise_min(A股 envelope, 美股 L1 ceiling)`（逐字段取更保守值），合成函数为纯函数；合成结果走与切片 3 相同的基准映射得到港股许可区间。港股取价并入现有生产 QuoteProvider（yfinance `.HK`），废弃 `stock_daily_fetcher` 的港股 None 分支；`.HK` 取价失败沿用 stale 降级规则。
- **envelope 引擎零改动**：`compute_envelope` / `compute_china_envelope` 及其历史落盘格式不动；P1 只新增消费方。
- **openspec 规格同步**：`trending-up-analysis` 与 `trading-strategy-ui` 中废弃的 Requirement 按 OpenSpec 流程标记移除；`position-advisor` spec 重写以反映账本数据源与新骨架。
- **UI 变更**：总资产页增加许可区间对照渲染（遵循可视化三规则，ADR-0015）；市场约束页保留现有 gauge，新增"占总资产许可区间"视角；港股视图进入市场约束页（不新建引擎页）。

## Testing Decisions

- **好测试的标准**（沿用 P0）：只测外部行为（构造输入 → 纯接口/门面 → 断言业务事实），不测内部表结构、SQL 与实现痕迹；测试永不走网络、不读系统时间。
- **被测接缝（已与用户确认）**：
  - 切片 1：`trending_up.analyze()` 输出 + 交易计划文本生成函数——删除后断言输出**不含**金字塔/止损字段，**仍含**确认清单/阶段/衰竭字段（保留部分的回归保护）；沿用 `tests/test_trending_up.py` 先例。
  - 切片 2：`compute_advisory()`（纯函数，构造持仓断言排序与分级）+ Ledger→Advisor 适配层（temp SQLite 端到端）+ 新北向信号函数（构造序列断言活跃度/方向输出，含 None/缺失数据与阈值边界）；断言旧 ±5% 调整项不再存在于体制计算链路。
  - 切片 3：战术偏移纯函数（envelope + 基准 → 许可区间；断言 clamp、基准未设定、空账本边界）+ 门面聚合（temp SQLite + 注入 QuoteProvider，沿用 `tests/test_ledger.py` 模式）。
  - 切片 4：港股合成纯函数（构造 A股 envelope × US L1 断言逐字段取保守值）+ QuoteProvider 注入测试 HK 取价路径；yfinance `.HK` 壳手动验证。
- **测试四象限**（沿用项目惯例）：正常路径、边界阈值、None/缺失数据、状态转换。
- **不测的薄壳**：Streamlit 页面、CLI 参数解析、yfinance 取价壳——手动运行验证（现有项目惯例）。

## Out of Scope

- P1.5 简版周报、P2 主线记分卡（含北向新信号的阈值年度校准仪式材料）、P3 尽调卡与基金替代性审查（基金 conviction 的自动化挂在 P3）
- AH 溢价指标的计算实现（当前无稳定数据源，保留占位；南向资金维持现状仅展示）
- IA 五页全量改版（P1 只改涉及页面；首页三问结构不动）
- envelope 引擎阈值调整、美股 L1/L2/L3 内部逻辑改动
- import 边界的架构测试（ADR-0017 定为 P1.5 起生效）
- 邮件告警、仪式调度（P4）
- `.scratch/convergence-plan-2026-08.md`（ADR-0018 引用）当前不在仓库中，其战术现金池规则不进 P1 范围
