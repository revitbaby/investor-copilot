# P0 总资产账本（Total Asset Ledger）

## Problem Statement

我是一名中国大陆个人投资者，总资产约 500 万人民币，分布在 A 股、港股、美股三个市场，其中约 40% 是天天基金上的公募基金（含 QDII）。今天没有任何一个地方能回答我最基本的三个问题：

1. **我现在的真实暴露是什么？**——基金不穿透，我以为的"A股/美股/AI 暴露"和真实值可能差 20 个百分点；QDII 基金里的美股 AI 持仓可能让我的卫星仓早已超过 25% 上限而不自知。
2. **我偏离基准了吗？**——没有统一账本，战略配置基准无从对照。
3. **我的 10 年 5 倍目标在轨吗？**——没有周期性的估值快照序列，真实年化收益无法计算，目标进度全凭感觉。

已建成的宏观体制引擎（美股/A 股 Target Position Envelope）没有"我"的数据可以约束——所有裁决（ADR-0001 至 0017）都要在总资产账本上计算，而账本还不存在。

## Solution

建立**总资产账本**：一个 SQLite 单库承载的、人民币计价的、覆盖三市场股票+基金+现金的唯一账本。数据半自动进入——基金侧由 Agent 仪式层调天天基金 Skill 自动拉取并经写入接口入库，股票和现金由我低频手工录入；系统每周打一次估值快照（汇率自动折算）。基金经 **X-Ray 透视**穿透到市场和主线暴露，从而首次算出**卫星仓真实占比**。Streamlit 新增「总资产」首页，按序回答三个问题：偏离基准了吗（基准未设定时显示真实暴露待我定基准）、卫星仓超没超 25%、目标进度如何（真实年化 vs 17.5% 需求线）。

P0 是纯绿地开发（ADR-0017）：四个新模块域，不触碰任何现有市场引擎代码。

## User Stories

1. 作为个人投资者，我想让 Agent 通过天天基金 Skill 自动拉取我的基金持仓和净值并写入账本，这样占我 40% 资产的基金部分不需要手工维护
2. 作为个人投资者，我想手工录入/更新我的股票持仓（市场、代码、股数、成本），这样我每月为数不多的几笔交易能以最低成本进账
3. 作为个人投资者，我想手工登记各账户的现金余额（人民币/港币/美元），这样账本覆盖我 100% 的金融资产
4. 作为个人投资者，我想让每笔持仓变动留下交易流水记录，这样未来复盘时能重建任意时点的持仓状态
5. 作为个人投资者，我想让系统每周自动打一次总资产估值快照（人民币计价、汇率自动折算），这样目标进度和偏离监控有连续的时间序列可算
6. 作为个人投资者，我想看到总资产的当前估值和按市场（A股/港股/美股/现金）的暴露分布，这样我第一次拥有"我的真实仓位"的单一事实来源
7. 作为个人投资者，我想让我的基金被 X-Ray 穿透到市场暴露（例如某 QDII 基金 = 95% 美股 + 5% 现金），这样市场暴露统计反映的是真实暴露而非账户表面分类
8. 作为个人投资者，我想给持仓（股票或整只基金）打上主线标签（如"AI 算力"）并标记是否属于卫星仓，这样卫星仓的边界是我显式定义的
9. 作为个人投资者，我想看到穿透后的卫星仓真实占比及其对 25% 上限的距离，这样 ADR-0002 的核心风控第一次可被验证
10. 作为个人投资者，我想看到目标进度仪表盘——从起点以来的真实年化收益 vs 达成 10 年 5 倍所需的 17.5% 需求线，这样每年的目标对质（ADR-0003）有数据基础
11. 作为个人投资者，我想在录入战略配置基准区间后看到各市场"实际 vs 基准区间"的偏离视图，这样首页第一问（偏离了吗）有答案；基准未设定时，页面应引导我"先看真实暴露、再定基准"而不是报错
12. 作为个人投资者，我想在 Streamlit「总资产」首页按序看到三个问题的答案（偏离/卫星占比/目标进度），且首页没有任何市场行情图，这样打开工具第一眼看到的是"我"而不是市场
13. 作为 Agent 仪式层，我想通过命令行写入接口（传 JSON）把天天基金 Skill 拉到的数据写进账本，而不是直接操作数据库文件，这样账本一致性由确定性内核保障（ADR-0014）
14. 作为 Agent 仪式层，我想在传入格式错误或内容可疑的数据时被拒绝并收到明确的错误说明，这样我的概率性输出不会污染账本
15. 作为个人投资者，我想让同一周重复打快照是幂等的（覆盖而非追加重复行），这样调度重跑不会弄脏时间序列
16. 作为个人投资者，我想在某些行情数据取不到时（停牌、API 失败），快照使用最近有效价并将该快照标记为 stale，这样快照序列不断档、我也知道哪些数字不新鲜（沿用现有 stale 模式）
17. 作为个人投资者，我想看到每只基金 X-Ray 穿透结果的数据日期（基金季报的滞后性），这样我知道穿透暴露是"截至几月"的近似值
18. 作为个人投资者，我想查看历史快照序列（估值、市场暴露、卫星占比随时间的变化），这样周报（P1.5）和年度对质有素材
19. 作为个人投资者，我想让账本数据只存在于本地文件（SQLite 单文件），不上传任何云端，这样我的财务隐私风险最小化
20. 作为个人投资者，我想用一条命令验证账本的完整性（快照断档、持仓与穿透版本错位、汇率缺失），这样手工数据的质量问题能被主动发现而非静默传导

## Implementation Decisions

- **新建 ledger 域（绿地）**：账本实体、聚合查询、写入校验全部在新域内实现；不修改任何现有市场引擎与取数模块（ADR-0017）。新域只准依赖现有 analysis/data/utils 层，不准依赖 UI 层。
- **持久化**：SQLite 单库（ADR-0014），实体五组——持仓（股票/基金/现金，多币种）、交易流水（append-only）、周度快照（含估值明细与 stale 标记）、基金 X-Ray 穿透结果（带数据日期版本，与拉取时点的持仓绑定）、主线映射（标的/基金 → 主线标签 + 卫星仓 flag）。市场数据缓存维持现有 CSV 模式不动。
- **唯一接缝 = Ledger Facade**：所有读写能力收敛为一个门面。两个注入点：QuoteProvider（股价/基金净值/汇率由调用方注入）与显式快照日期。CLI 写入命令（供 Agent）、Streamlit 总资产页（只读）、周度快照 job 全部是门面的薄壳。
- **写入路径**：Agent 经 `python -m` 风格的 CLI 命令传 JSON 写入（基金持仓/净值）；股票与现金的手工录入同样走 CLI 命令（Agent 会话代录也走这条路）。UI 层无任何写入能力（ADR-0014/0015）。
- **校验规则在门面内强制**：必填字段与类型校验、币种白名单（CNY/HKD/USD）、穿透权重求和 ≈ 100% 容差校验、可疑值拒绝（如基金净值为 0 或负数）、快照幂等（同周覆盖）。
- **X-Ray 精度策略**：市场级暴露用基金披露的资产配置比例（股票/债券/现金 + 地区）计算，为季报级近似；每条穿透结果记录 as-of 日期。主线归属不做自动推断——基金/股票的主线标签由用户手工指定（自动推断留给 P2 之后）。
- **卫星仓占比算法**：卫星占比 = Σ(标记为卫星的直接持仓市值 + 标记为卫星的基金市值 × 该基金权益暴露比例) ÷ 总资产。以穿透后口径计算，直接对照 25% 上限。
- **记账货币人民币**；汇率在快照时通过现有市场数据取数层获取（QuoteProvider 的生产实现组装现有 loader），测试中注入。
- **战略配置基准**以配置文件形式存在（各市场 min%–max%），支持"未设定"状态；基准数字本身在 P0 交付后、看到真实穿透暴露时由用户裁定（ADR-0011 开放项）。
- **周度快照 job**：headless 入口（ADR-0012），组装"现有取数层 → QuoteProvider → 门面打快照"，由 Agent 仪式层或本地调度器触发；job 本身不含业务逻辑。
- **总资产首页**：Streamlit 新页面，只读渲染门面的聚合输出；遵循可视化三规则（区间画色带、图上标"我"、红色只给需要动作的事，ADR-0015）；新增文案只注册中文 key（ADR-0016）。
- **天天基金 JSON schema**：写入接口的输入契约在实施第一步与 ttfund Skill 的实际输出对齐后钉死（开放项），门面对 schema 版本做显式校验。

## Testing Decisions

- **好测试的标准**：只测门面的外部行为（写入 → 聚合输出），不测内部表结构与 SQL 细节；断言业务事实（"卫星占比 = 23.4%"），不断言实现痕迹。
- **被测模块**：唯一被测对象是 Ledger Facade。用 temp 路径的 SQLite、构造的 QuoteProvider 数据、显式日期——测试永不走网络、不读系统时间。
- **覆盖面**（沿用项目测试四象限：正常路径、边界阈值、None/缺失数据、状态转换）：
  - 写路径：基金持仓 JSON 入库、股票/现金录入、交易流水生成
  - 读路径：人民币总估值（多币种折算）、市场暴露（含 X-Ray 穿透）、卫星占比（持仓 × 穿透 × 主线映射三表联动）、目标进度年化计算
  - 一致性：快照幂等、脏数据拒绝（缺字段/负净值/权重和越界）、穿透版本错位拒绝、stale 传播
  - 边界：基准未设定、账本为空、单一市场、汇率缺失
- **先例**：`tests/test_china_regime.py`（99 个测试）的构造输入 → 调纯接口 → 断言输出风格。
- **不测的薄壳**：CLI 参数解析壳、Streamlit 页面、周度 job 组装壳——经手动运行验证（现有项目惯例）。

## Out of Scope

- P1 及以后的全部内容：体制引擎接入总资产层与战术偏移计算、去糟粕拆除、周报生成、主线景气记分卡、尽调卡、基金替代性审查、邮件告警、IA 五页全量改版（P0 只交付总资产首页这一页）
- import 边界的架构测试（ADR-0017 定为 P1.5 起生效）
- 基金主线归属的自动推断（P0 手工打标）
- 券商 API 对接（ADR-0007 已否）
- 账本建立日之前的历史交易回填（起点即当前持仓快照，历史收益从起点算起）
- 战略配置基准数字的裁定（P0 只提供配置位和"未设定"状态）

## Further Notes

- **隐私**：账本含真实财务数据，SQLite 文件位于 `data_cache/`（已被 gitignore 覆盖，实施时须确认），永不入 git、永不上云。
- **开放项**（实施时解决）：ttfund Skill 输出的 JSON schema 钉死；FX 取数具体 ticker（USDCNY/HKDCNY）与现有 loader 的复用方式。
